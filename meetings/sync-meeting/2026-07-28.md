josh: What is the state of default features?

ed: a feature subtraction proposal has transition points that can't be done across editions. So it's not sufficient. There is still a usecase for default-features = false and feature subtraction. Still needs a champion. What sigel should we use? Should it subtract from default-features, or any feature in the list

josh: I'd be interested in helping resolving these. I'd like to better understand default-features=false. Could it be better addressed by global features. The other main usecase is the "choose a backend" case.

ed: clap can serve as an example for both these cases. For clap-complete, you have to remember to subtract 20-30 things. I want default-features=false.

josh: "I'm part of the same ecosystem, so I have a matching version, so `default-features = false` is easier than listing every new subtractive feature?"

ed: I'd like a "feature bases" idea. Subtraction + no default might be enough, but it could be extended to have custom base set of features.

josh: could we get a first pass (subtractive) without trying to design everything

ed: `no-default` would still be important. There's an RFC.
