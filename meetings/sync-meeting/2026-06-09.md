## (backlog) --bin B resolves features differently than -p B in a workspace

https://github.com/rust-lang/cargo/issues/8157

`cargo run --bin NAME` resolves features differently because it has an implicit `--workspace` in order to find a binary with that name. Unfortunately our target-proposal filtering code runs after resolution.

It may be possible to have the code that adds the implicit `--workspace` to instead scan the workspace members for a binary with the given name, and then add implicit `-p` flags for those crates. ehuss had some comments about that being tricky, but can't remember what the difficulty might be.

ehuss: Maybe conditionally approve this if the implementation doesn't look too difficult and we can't think of potential edge cases?

Eric: Do people care that we changed the behavior, since that 'd be a breaking change?

Scott: Couldn't they use the unstable feature resolver?

Eric: If we changed it, they could use the feature resolver option or pass `--workspace`

Scott: Either would be fine.

Arlo: Don't know enough on feasibility, but...

Eric: It does seem confusing to people.

Arlo: It's one of the things I found confusing with worksapces.

Eric: I didn't anticipate that feature unification would be an issue. Before we added this, `--bin FOO` resulted in a bad error message. 

Ross(chat): tbh, I thought you needed `-p` if you use --bin if you are in a workspace 

Scott: There might be people who built single binaries and would run into clashes when ?? tests

Eric: Maybe. You have the same problem with dev-dependencies.

Scott: I don't really know if that's a breaking change. The only reason I could think of is if someone has an unspecified dependency that gets enabled through feature unification. That would be good to surface at some level.

Scott: Testing on nightly until a full release cycle would help us get feedback.

Eric: Hard to get feedback in testing. The number of people affected could be small. Hard to decide how to make a change like this.
