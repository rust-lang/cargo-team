## (backlog) Export the vcs information as environment variable

(continue from 2026-10-06)

https://github.com/rust-lang/cargo/issues/11456

Ed: We might want to be moving forward on this. We talked about this recently. This is one of the ways for us to eventually kill build scripts.

Josh: The one downside of this is that it makes it so that building the same source code in or out of a git repo will produce different results.

Ed: I have brainstorming on the issue itself which addresses Josh's concerns. If there's vcs-info, it takes precedence from talking to git directly. That way you can override it and still have this if you don't have git.

Josh: I do think as long as we limit ourself to things we can get from vcs-info and make sure the results there and from build from source is identical, that seems fine.

Ed: wondering whether this would be a profile ?? can't guarantee people that it would be there

Josh: Requiring you to turn it on seems like a feature. The thing that tips me towards actually doing this is that people do it anyway whether we'd like them to or not, via `build.rs`. If we make this information available to them and limit it to what's available via VCS info, that would help compared to `build.rs`.

Weihang: Make this vcs info non-overidable from parent process etc. otherwise it would be a mess

Ed: We talked about it more generally, then found this issue and added this to the backlog. They tried to implement rerun-if-changed digging deep into information from git. If you want to get a proper rerun-if-changed, this gets really messy

Jacob: Lots of complexity there.

Ed: You shouldn't say rerun-if-change for conditionally present env vars. The current version of our depinfo files doesn't handle whether the env var is present or not.
